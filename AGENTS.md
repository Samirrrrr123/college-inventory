# Работа над проектом

- Не добавлять комментарии в исходный код, тесты и конфигурационные файлы. Пояснения размещать в Markdown-документации.
- Использовать понятные названия и небольшие функции; избегать лишних зависимостей и абстракций.
- Самир отвечает за frontend/, общий Compose, CI и деплой. Артём отвечает за backend/, схему БД и миграции.
- По согласованию с Самиром модуль backend/src/auth, аккаунты, сессии, миграция 202610200001_auth и их интеграция с frontend добавлены со стороны Самира. Артём продолжает предметную область и расширяет существующую схему миграциями; второй модуль авторизации не создавать.
- По отдельному разрешению Самира модуль backend/src/circulation, миграция 202610210001_circulation и экран /app/requests реализованы со стороны Самира. Использовать готовые заявки, выдачи и возвраты; не создавать параллельный модуль. Оставшиеся предметные функции продолжает Артём.
- По разрешению Самира необходимые для интеграции исправления можно вносить и в часть другого участника без предварительного ожидания согласования. После изменений подготовить короткое описание для передачи Артёму через Самира. Не отправлять Артёму сообщения самостоятельно.
- Работать в feature-ветках и публиковать проверенные изменения через PR. По просьбе Самира обязательный Approve отключён: после успешных проверок можно сливать PR без ожидания Артёма. Не отмечать командное ревью выполненным без фактической проверки вторым участником.
- Не выдавать демонстрационный frontend за готовое fullstack-приложение. Не заявлять о проверках, которые не выполнялись.
- Не коммитить секреты, .env, node_modules, загруженные пользователями файлы и отчёты с личными данными.
