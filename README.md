# Инвентарь

Система учёта оборудования и аудиторий колледжа. Командный проект учебной практики по специальности 09.02.07 «Информационные системы и программирование».

## Команда

- **Самир:** Figma, frontend, адаптивность, темы и RU/EN, тесты компонентов и e2e, общий Docker Compose, CI и деплой.
- **Артём:** backend, PostgreSQL, миграции и seed, авторизация и права, OpenAPI, серверные тесты и Dockerfile сервера.
- Вместе согласуем требования и API, проверяем PR друг друга и интегрируем приложение. Дневники и индивидуальные отчёты у каждого свои.

## Возможности и роли

Преподаватель подаёт заявки и просматривает свои выдачи. Лаборант ведёт оборудование, выдачи, возвраты, перемещения и инвентаризацию. Администратор управляет пользователями, ролями и справочниками.

Планируются каталог с серверными поиском, фильтрами, сортировкой и пагинацией, загрузка файлов, личный кабинет, статистика, аудит и экспорт XLSX. Настройки интерфейса: светлая, тёмная и системная тема, русский и английский языки.

## Стек

- React, TypeScript strict, Vite, React Router, Tailwind CSS.
- Node.js, Express, TypeScript, Prisma, PostgreSQL.
- REST API, OpenAPI 3, Swagger UI.
- Vitest, Testing Library, Supertest, Playwright.
- Docker Compose и GitHub Actions.

Точные совместимые версии фиксируются в манифестах и lock-файлах. Изменения общего стека согласуются участниками.

## Дизайн

[Макеты Figma](https://www.figma.com/design/jIVQxAXjthCzGjexpRL1J6): шесть основных экранов в двух темах, мобильные примеры, формы и UI-kit. Данные в макетах демонстрационные.

## Целевая структура

```text
frontend/       # интерфейс Самира
backend/        # сервер Артёма
docs/           # требования, API, схемы и отчёты
.github/        # шаблоны PR и CI
compose.yaml    # общий запуск
```

Исходный код и инфраструктура добавляются отдельными PR; приведённая структура описывает план проекта.

## Совместная работа

1. Получить актуальную main через `git fetch origin` и `git pull --ff-only` в чистой рабочей копии.
2. Создать feature-ветку для своей задачи.
3. Сделать изменения и проверки, создать осмысленный коммит.
4. Отправить ветку и открыть Pull Request.
5. Получить ревью второго участника, затем объединить PR.

Контракт API согласуем до подключения frontend: маршруты, поля, роли, статусы, авторизация, ошибки, списки и файлы должны совпадать. Не коммитим секреты и `.env`. Защита main и обязательные проверки настраиваются отдельно в GitHub; сам README их не включает.
