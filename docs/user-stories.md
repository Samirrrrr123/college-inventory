# Пользовательские истории

Согласуемый список для канбан-доски. Критерии относятся к итоговому приложению; наличие макета или деморежима не означает их выполнение.

| ID | История | Критерии приёмки |
|---|---|---|
| US-01 | Как преподаватель, я хочу зарегистрироваться и войти, чтобы работать со своими заявками. | Email уникален; пароль хешируется; регистрация не назначает привилегии; access/refresh и выход работают. |
| US-02 | Как пользователь, я хочу восстановить пароль, чтобы вернуть доступ. | Одноразовая ссылка ограничена сроком; повторное использование отклоняется; разрешён вывод ссылки в лог. |
| US-03 | Как преподаватель, я хочу находить оборудование, чтобы выбрать нужную технику. | Поиск, фильтры, сортировка и пагинация выполняются сервером; ошибки и пустые результаты понятны. |
| US-04 | Как лаборант, я хочу вести каталог, чтобы сведения об оборудовании оставались актуальными. | Создание/просмотр/редактирование/удаление доступны по правам; номер уникален; удаление подтверждается; история сохраняется. |
| US-05 | Как лаборант, я хочу прикреплять фото и документы, чтобы описать оборудование. | Тип/размер проверяются клиентом и сервером; имена безопасны; закрытые вложения доступны только по правам. |
| US-06 | Как преподаватель, я хочу подать заявку, чтобы получить оборудование для занятия. | Выбраны оборудование и даты; неверные даты отклоняются; заявка привязана к текущему пользователю. |
| US-07 | Как лаборант, я хочу рассматривать заявки, чтобы организовать выдачу. | Разрешены только допустимые переходы статусов; решение видно автору; чужая роль не вызывает операцию через API. |
| US-08 | Как лаборант, я хочу оформлять выдачу и возврат, чтобы знать, у кого находится техника. | Недоступную единицу нельзя выдать повторно, в том числе конкурентно; возврат фиксируется один раз. |
| US-09 | Как лаборант, я хочу учитывать аудитории и перемещения, чтобы знать местоположение оборудования. | Аудитории редактируются по правам; перемещение сохраняет исходную/целевую аудиторию, автора и дату. |
| US-10 | Как лаборант, я хочу проводить инвентаризацию, чтобы выявлять расхождения. | Есть состав проверки, фактическое наличие, результат, автор и завершение; история доступна для просмотра. |
| US-11 | Как пользователь, я хочу редактировать профиль и смотреть свою историю, чтобы управлять учётной записью. | Профиль и смена пароля валидируются; история ограничена правами; подстановка ID не раскрывает чужие данные. |
| US-12 | Как администратор, я хочу управлять пользователями и ролями, чтобы контролировать доступ. | Работают назначение роли и блокировка; блокировка прекращает доступ; последний администратор защищён от случайного отключения. |
| US-13 | Как лаборант, я хочу видеть статистику, чтобы оценивать состояние фонда. | Дашборд отображает данные из БД и график либо сводку; числа согласованы с записями и правами пользователя. |
| US-14 | Как администратор, я хочу видеть аудит и экспортировать XLSX, чтобы проверять операции и готовить отчёты. | В аудите автор/действие/объект/время без секретов; XLSX учитывает фильтры и права, открывается как таблица. |
| US-15 | Как пользователь, я хочу выбирать тему и RU/EN, чтобы удобно работать с разных устройств. | Есть светлая/тёмная/системная тема, полный перевод интерфейса, сохранение выбора и адаптивность 360–1920 px. |

Ответственные за реализацию распределяются по слоям: Самир — интерфейс и общий запуск, Артём — API и данные. Каждая история может быть разбита на отдельные frontend/backend/test-задачи. Перенос историй на реальную канбан-доску ещё требуется.
