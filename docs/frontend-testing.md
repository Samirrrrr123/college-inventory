## Компоненты

1. Поиск и фильтр оборудования, пустой список, сброс фильтров.
2. Повтор инвентарного номера: ошибка формы без её закрытия.
3. Запрет удаления оборудования, связанного с заявками или выдачами.
4. Сохранение тёмной темы и английского языка после повторного открытия.
5. Корректные настройки по умолчанию при повреждённом localStorage.
6. Отсутствие административного раздела у преподавателя и отказ при прямом открытии маршрута.
7. Преподаватель видит только свои демонстрационные заявки.
8. Вход: обязательные поля, формат email и фокус на первой ошибке.
9. Регистрация: совпадение паролей, отсутствие выбора привилегированной роли и отсутствие локального аккаунта; после корректного заполнения пароли очищаются.
10. Показ пароля и очистка при переходе между формами.
11. Восстановление: ссылка без кода не даёт отправить форму; новый пароль проходит проверку длины.
12. Повтор номера аудитории отклоняется, аудитория с оборудованием не удаляется.
13. Новая категория появляется в фильтре оборудования; связанную категорию удалить нельзя, свободную можно.
14. Последнего администратора нельзя отключить; email другого пользователя отклоняется без учёта регистра.
15. История профиля сохраняется после переименования; чужой email нельзя присвоить себе.
16. Заявка с занятым предметом не выдаётся частично: свободный предмет остаётся доступным, выдача не создаётся.
17. Прошедший срок возврата отклоняется при выдаче.
18. Смена пароля проверяет отличие от текущего и очищает пароли после корректного заполнения, без ложного сообщения об успехе.
19. Конкурентные запросы используют один refresh, токен не попадает в localStorage/sessionStorage.
20. Истёкший access приводит к одному обновлению и одному повтору запроса.
21. При отозванном refresh защищённый запрос не отправляется.
22. Справочник из 101 записи загружается двумя страницами без потери последней записи.
23. Нулевой этаж передаётся в параметрах запроса; пустые фильтры пропускаются.
24. Рабочий каталог показывает результат серверного поиска без дополнительной локальной фильтрации; преподавателю не показаны кнопки изменения.
25. Ошибка списка показана отдельно от пустого результата, повтор запроса загружает данные.
26. Ответ устаревшего поиска не заменяет результат нового запроса.
27. Форма заявки проверяет цель и непустой состав до обращения к API.
28. Выбранное оборудование сохраняется при смене серверной страницы; в запрос отправляются только цель и выбранные ID, без подстановки автора.
29. Конфликт доступности комплекта оставляет форму выдачи открытой с сообщением сервера.

## Браузер

1. Создание оборудования, поиск, открытие карточки, закрытие через Escape с восстановлением фокуса, подтверждение удаления.
2. Тёмная тема и RU/EN сохраняются при перезагрузке; системная тема реагирует на смену цветовой схемы устройства.
3. Шесть разделов приложения и четыре формы доступа открываются без ошибок JavaScript и горизонтального переполнения на ширинах 360, 768, 1440 и 1920 px.
4. Переход со входа на регистрацию, ошибка повтора пароля, понятное сообщение при сетевом отказе, очистка пароля, тёмная тема и EN на телефоне, отдельный переход к демоверсии.
5. Создание и подтверждение удаления аудитории, отмена удаления, создание/редактирование категории и её появление в каталоге, создание и разблокировка демонстрационного пользователя.
6. Преподаватель создаёт заявку на два предмета; сотрудник одобряет её, выдаёт комплект, видит изменение статуса в каталоге и принимает оба предмета обратно одной операцией.
7. Формы аудитории, пользователя, категории, выдачи и смены пароля помещаются на экране 360 px в тёмной теме на английском; кнопки сохранения/отмены доступны.
8. Настоящая регистрация, вход, восстановление сессии после перезагрузки, сохранение профиля в PostgreSQL, проверка HttpOnly cookie и выхода. Аккаунт помещается на 360, 768, 1440, 1920 px.
9. Смена пароля через настоящий профиль отзывает сессию; старый пароль отклоняется, новый позволяет войти.
10. Лаборант создаёт категорию, аудиторию с нулевым этажом и оборудование; данные сохраняются после перезагрузки. Проверены редактирование, удаление и отказ удаления связанной категории.
11. Преподаватель использует серверную пагинацию, сортировку и фильтр статуса; интерфейс остаётся доступен только для чтения, прямой запрос изменения получает HTTP 403.
12. Три рабочих списка и формы проверены на ширинах 360, 768, 1440, 1920 px; английская тёмная тема и кнопки форм доступны на телефоне.
13. Настоящий преподаватель подаёт заявку на два предмета; лаборант одобряет её и выдаёт весь комплект со сроком возврата. Автор видит выдачу, но не может оформить возврат. Лаборант возвращает весь комплект; обе единицы доступны, история сохранена, повторный возврат через API отклоняется.
14. Рабочие вкладки заявок, активных выдач и возвратов проверены на 360, 768, 1440, 1920 px; формы заявки и прямой выдачи доступны на телефоне в английской тёмной теме.

Визуально проверены шесть разделов на desktop, каталог на телефоне и профиль в тёмной теме на английском. SVG-иконки из Figma загружаются без ошибок.

Дополнительно проверены формы входа, регистрации, восстановления и нового пароля на desktop и телефоне, в том числе регистрация в тёмной теме на английском. Иллюстрация с экрана входа взята из Figma и отображается в исходном размере 100 × 100 px.

Проверены пять новых форм управления на desktop и телефоне (RU/EN, светлая/тёмная тема). В форме выдачи длинный список оборудования прокручивается внутри диалога; весь комплект отображается в выдаче и подтверждении возврата.

Рабочие каталог, аудитории и категории визуально проверены на desktop в светлой теме и на телефоне в тёмной теме на английском, включая формы создания всех трёх сущностей. Ошибок JavaScript не обнаружено.

## Исправленные дефекты

- Перекрытие радиокнопки системной темы иконкой мешало нажатию. Вся карточка темы теперь является областью выбора; повторный браузерный сценарий прошёл.
- Для мобильной навигации в тёмной теме подключены соответствующие иконки из макета.
- История профиля раньше фильтровалась по имени автора и исчезала после смены имени. Теперь используется стабильный идентификатор пользователя; сценарий покрыт тестом.

## Границы проверки

Проверка маршрутов по демонстрационной роли не доказывает безопасность приложения: авторизация и доступ к данным должны отдельно проверяться на сервере.

На этом компьютере нет Docker, поэтому образ локально не собирался. В workflow `Frontend` предусмотрена отдельная сборка Docker на GitHub Actions. Статус конкретного запуска нужно смотреть в PR.

Серверные тесты и покрытие аккаунтов, каталога и выдач описаны в [testing-report.md](testing-report.md). Реальная загрузка файлов, инвентаризация и управление пользователями ещё не проверены. Публичный запуск аккаунтов и каталога подтверждён; новый блок дополнительно проверяется после обновления VPS. Общий Compose проверяется в CI; локально Docker не установлен. Без `RUN_API_TESTS=1` семь браузерных сценариев с API пропускаются; для каталога и выдач также нужен пароль тестовых ролей в `SEED_PASSWORD`.
