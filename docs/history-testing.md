## Повторение

Для полного backend-прогона нужна отдельная PostgreSQL с именем БД, заканчивающимся на `_test`, без заранее созданных активных администраторов. Задать NODE_ENV=test, DATABASE_URL, CLIENT_ORIGIN и разные ACCESS_SECRET/REFRESH_SECRET длиной от 32 символов. Тесты создают и удаляют только свои записи. Не использовать рабочую базу.

При заданных переменных окружения:

```sh
pnpm --dir backend install --frozen-lockfile
pnpm --dir backend generate
pnpm --dir backend migrate
pnpm --dir backend lint
pnpm --dir backend format:check
pnpm --dir backend typecheck
pnpm --dir backend test
pnpm --dir backend build
pnpm --dir frontend install --frozen-lockfile
pnpm --dir frontend lint
pnpm --dir frontend format:check
pnpm --dir frontend typecheck
pnpm --dir frontend test
pnpm --dir frontend build
```

Для браузера подготовить другую отдельную БД, применить миграции и обычный seed, запустить API на 3001 с CLIENT_ORIGIN=http://127.0.0.1:5173. Установить Chromium командой `pnpm --dir frontend exec playwright install chromium`. Задать RUN_API_TESTS=1 и тот же SEED_PASSWORD, затем:

```sh
pnpm --dir frontend exec playwright test e2e/history-api.spec.ts
```

Playwright сам запускает Vite на 5173. Без RUN_API_TESTS/SEED_PASSWORD эти два сценария намеренно пропускаются; пропуск не считается проверкой.

Общий CI уже запускает серверные тесты на PostgreSQL 18, все браузерные сценарии с API, Docker Compose, production-конфигурацию и проверку через Nginx. Его файлы не менялись; новые тесты подхватываются автоматически. Итог актуального коммита смотрится в Checks нового PR; локальный запуск не выдаётся за CI или проверку VPS.
