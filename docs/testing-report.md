## Объект и среда

Проверены React-интерфейс, модули аккаунтов, каталога, заявок и выдач Express с PostgreSQL. Заявки, выдача и возврат комплектов проверены через настоящий API; инвентаризация и управление пользователями пока проверены только в демоверсии.

Локальная среда: Windows, Node.js 24.19.0, pnpm 11.25.0, Chromium Playwright. Серверные интеграционные тесты выполнялись с отдельной настоящей PostgreSQL, не с подменой или SQLite. В GitHub Actions использовались Ubuntu runner и PostgreSQL 18; там же проверен Docker Compose. Локально Docker не установлен.

## Frontend и браузер

Подробный список локальных проверок интерфейса приведён в [frontend-testing.md](frontend-testing.md). Основные группы:

- Формы проверяют обязательные поля, email, совпадение паролей, уникальные значения справочников и понятные ошибки. Проверяются фокус, закрытие диалога и подтверждение удаления.
- Темы и RU/EN сохраняются; системная тема реагирует на настройки устройства. Шесть основных экранов и формы доступа не имеют горизонтального переполнения на проверенных ширинах.
- Демооперации проверяют комплектную заявку, одобрение, выдачу, изменение статусов каталога и возврат. Отдельный тест запрещает частичную выдачу, если один предмет занят. Это не проверка серверной транзакции выдачи.
- Реальные сценарии проверяют регистрацию, вход, сохранение профиля в БД, восстановление сессии после перезагрузки, выход и смену пароля. Проверяется, что refresh cookie имеет HttpOnly, а access и пароль отсутствуют в localStorage/sessionStorage.
- Каталог проверяется через настоящий API: создание категории, аудитории с нулевым этажом и оборудования, редактирование, сохранение после перезагрузки, отказ удаления связанной категории и удаление свободных записей. Для преподавателя проверены серверные пагинация, сортировка, фильтр статуса и HTTP 403 при попытке изменения.
- Компонентные проверки рабочего списка отделяют сетевую ошибку от пустого результата, проверяют повтор запроса и игнорирование устаревшего ответа поиска. Справочник из 101 записи загружается без обрезания до одной страницы.
- Тесты API-клиента проверяют одно обновление сессии для параллельных запросов, один повтор после истёкшего access и отказ без запроса данных при отозванном refresh.
- Компоненты новых форм проверяют обязательную цель и состав, сохранение выбора между серверными страницами и сохранение открытого диалога при HTTP 409. Реальный браузерный сценарий проходит заявку на два предмета, одобрение, выдачу, просмотр автором, возврат и повторный отказ возврата. Отдельно проверены вкладки и формы на 360–1920 px с тёмной темой и EN.

## Как воспроизвести

Для frontend установить зависимости и выполнить `lint`, `format:check`, `typecheck`, `test`, `build` из его каталога. Для браузера установить Chromium и выполнить `test:e2e`. Для семи сценариев с API дополнительно запустить backend, выполнить seed и установить `RUN_API_TESTS=1` и соответствующий `SEED_PASSWORD` в окружении тестов.

Для backend задать тестовые переменные окружения, включая URL отдельной PostgreSQL с окончанием `_test`, разные секреты JWT и точный origin frontend. Применить миграции к этой тестовой базе, затем выполнить `pnpm test`. В репозитории не публикуются реальные `.env`, токены или пароль локальных тестовых аккаунтов.

Общий запуск и тестовые роли описаны в [README](../README.md), поля и правила API — в [OpenAPI](https://85.8.201.148/api/docs/). Полный порядок CI зафиксирован в workflow-файлах репозитория.

## Проверка публичного стенда

21.10.2026 на `https://85.8.201.148` проверены сертификат без обхода TLS-проверки, HTTP 200 страницы входа и готовность API. Chromium подтвердил вход администратора, восстановление сессии после перезагрузки, Secure/HttpOnly refresh-cookie, создание категории, её сохранение после перезагрузки и удаление. Проверены desktop и ширина 360 px; ошибок JavaScript не обнаружено. Временная категория удалена после проверки.

При первом запуске выявлена неверная настройка определения IP за Caddy/Nginx: лимит попыток входа объединял посетителей по адресу прокси. Добавлен `TRUST_PROXY_HOPS` с проверкой допустимого значения. Тест `backend/tests/proxy.test.ts` проверяет отдельные счётчики посетителей и невозможность сменить определяемый адрес дополнительным значением слева в заголовке.

После публикации PR #25 на том же HTTPS-стенде через интерфейс проверены заявка преподавателя на два предмета, одобрение лаборантом, выдача всего комплекта, сохранение после перезагрузки и возврат. Оба предмета снова доступны, запись возврата сохраняется в истории. Страница проверена на ширине 360 px; ошибок JavaScript нет. Миграция применена успешно; перед обновлением сохранена резервная копия БД, существующие записи и пароли сохранены.
